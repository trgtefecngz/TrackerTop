## Notes and decisions
- The lexer-only unit tests of the old TS scanner were replaced by behavioral span tests on the same inputs.
- Unterminated `it(` becomes a tree-sitter ERROR node and is recorded as a one-line test without call edges.
- smart_grep uses Unicode simple lowercasing. Turkish dotted/dotless I is not folded the Turkish way (a known limit).
- In the nested view, search, language filter and "Code Only" apply only to the Folders and Clusters layouts. The nested view always shows the whole project, so its counts stay complete.

## Product feedback from dogfooding (TrackerTop's own tools)
- `file_outline` on `graph.rs` saved 87%. It plus targeted line reads were enough to integrate into a 3k-line `ui.rs`.
- Missing: a way to read a line range around a symbol, such as an `impl` tail or a test module, without falling back to Read. `read_symbol` on `mod tests` would help.
- Missing: `file_outline` does not list callers of a private fn. For "who uses `GraphLayoutMode`" a grep was still needed. `impact_analysis` on an enum type would answer it.

## Kararını bekleyenler (decisions waiting for the user)
- **Should `.trackertop/notes/` be committed to git?** For now it stays local: `.trackertop/` is git-ignored, the conservative choice. Sharing notes needs a `!notes/` exception.
- `changes_since` only accepts git refs. A mode based on index generations would need stored old contents; it is not in v0.7.
- Release: version 0.7.0 is set in Cargo.toml, but nothing is tagged or released. That waits for your review.

## Open risks
- Other extractors (Python, Go, PowerShell, WGSL, docs) are still heuristic. They are flagged in outputs but not ported.
- The release MCP binary used by Claude Code is not rebuilt by this branch, so dogfooding uses the v0.6 tool behavior until a release.
- Call resolution by bare name creates false edges, for example `X::new` → `TrackerTopApp::new`. The nested view shows them faithfully, so its counts include them.
