## What exists
- `src/review/snapshot.rs`: the base commit is checked out into `.trackertop/review-base/<commit12>/` using a private `GIT_INDEX_FILE`. No worktree is registered, no hooks run, and the user's index is untouched. The newest 3 snapshots are kept. Monorepo subdirectories work.
- `src/review/mod.rs`: compares the working tree with the merge base. Each symbol is classified added, removed or modified, with `file:line` on both sides.
- Rules:
  - `broken-ref`: the call text is re-verified in the working tree.
  - `orphan`: a function that lost its last caller in this change, reported only if no graph caller is left and its name appears in no file git knows. Functions carrying framework attributes or decorators are skipped.
  - `impact`: ≥ 8 code dependents within 3 hops.
  - `untested`.
  - `new-cycle`: JS/TS/Python/Go only.
  - `cochange-miss`: from the base's history, needing ≥ 5 commits of the file, ≥ 4 shared and ≥ 60 %, and counting only commits of ≤ 12 files.
  - `bloat`.
- Output: Markdown, JSON and SARIF. SARIF paths are relative to the repository root and include the monorepo prefix. `--fail-on` exits 1.
- `review_changes` (MCP) reports resolved / new / unchanged findings against the previous review of the same base (table `review_findings`).
- Notes record the commit and a code hash, and are flagged POSSIBLY OUTDATED once the code changes. A dismissal holds only while its code is unchanged.
- `read_symbol` accepts `path:Lstart-end` and names the symbol around the range. Exact lookups come first; AMBIGUOUS and closest-match results are labelled.
- Rust type uses inside function bodies are edges, and a Rust type use resolves only to a type.
- Python and Go use tree-sitter; golden tests in each module.
- `indexer::EXTRACTOR_REVISION` (now **6**): an index written by another revision is re-parsed in full. Files that cannot be re-parsed lose their rows instead of keeping stale ones. **Bump it whenever an extractor's output changes.**

## Product feedback from dogfooding
- **Stale index after upgrades (fixed)**: unchanged files kept references from the old extractor. `TrackerEngine::finalize_inner` showed 0 callers instead of 19, so every call-edge fix was invisible on existing indexes. This was found because `orphan` candidates looked wrong.
- **Type users (fixed)**: `impact_analysis` on `Severity` listed 6 direct users, now 18, because body uses (`Severity::High`) are counted.
- The MCP server in this session is the v0.7 release binary, so the agent still saw the old fuzzy `read_symbols_batch` behaviour. The fixes reach agents only after a release.
- Still open (no type information, v0.9 LSP): `untested` fires on functions called only as `.push(…)`, `.map(span)` or through traits.

## Kararını bekleyenler
1. **Dismissals in CI**: `trackertop review --fail-on` (CLI and the planned Action) does not see dismissals made through MCP, because they live in git-ignored `.trackertop/` notes. CI can therefore fail on a finding the agent already dismissed. The design note recommends a committed `.trackertop-review.json` that carries code hashes. Nothing is implemented.
2. The other open questions in `docs/design/AI_PASS_AND_ACTION.md` §3: providers for the AI pass, and PR comment vs SARIF only.

## Known limits (left on purpose)
- `cochange-miss` on case-insensitive file systems: a path renamed only in case in history could be reported as "not in this change". This is rare, so it was not fixed.
- `orphan` cannot see dynamic dispatch, reflection or other repositories. The message asks the user to confirm before deleting.
