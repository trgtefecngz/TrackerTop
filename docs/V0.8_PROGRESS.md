## What exists (summary of runs 1–2)
- `src/review/snapshot.rs`: base commit checked out into `.trackertop/review-base/<commit12>/` with a private `GIT_INDEX_FILE` (no worktree, no hooks, user's index untouched), newest 3 kept; monorepo subdirectories work.
- `src/review/mod.rs`: `review(root, base)` compares the working tree with the merge base; symbols compared per file by (qualified name, kind), classified added/removed/modified with `file:line` on both sides.
- `src/review/rules.rs`: broken-ref (call text re-verified in the working tree), impact (≥ 8 code dependents in 3 hops), untested (says "no callers at all, grep first" when the graph has none), new-cycle (JS/TS/Python/Go only), bloat (> 3,500 tokens).
- `src/review/cochange.rs` (run 2): `cochange-miss` from `git log` at the base (300 non-merge commits, `--relative`). Thresholds: the touched file has ≥ 5 commits of ≤ 12 files, the partner shared ≥ 4 of them and ≥ 60 %. Looser thresholds (3 commits, ≤ 20 files) produced 4 noise findings on this repo from release commits; the strict ones leave 1 real habit (indexer.rs ↔ fsutil.rs, 7 of 10).
- `src/review/orphan.rs` (run 2): a function whose caller the change removed/rewrote, with no graph caller left AND its name absent (whole word) from every indexed code file outside its own body. On this repo vs v0.6.0: 51 graph-orphan candidates, all held back by the name check (correct: they are still named).
- `src/review/sarif.rs` (run 2): SARIF 2.1.0; a removed symbol points at the caller still using it. CLI `--fail-on low|medium|high` exits 1.
- `review_changes` (MCP): findings first, dismissed list, then "Since the previous review against `<base>`: N resolved, N new, N unchanged" (table `review_findings`, per base ref), then symbols.
- Notes carry commit + code hash; shown as POSSIBLY OUTDATED when the code changed; a dismissal holds only while its code is unchanged.
- Symbol lookups: exact id → `path::name` → exact qualified name → exact name (AMBIGUOUS listed) → fuzzy (labelled).
- **Index extractor revision (run 2)**: `indexer::EXTRACTOR_REVISION` stored in `meta`; an index from another revision is re-parsed in full (deletions still detected). Bump it whenever an extractor's output changes for unchanged source.
